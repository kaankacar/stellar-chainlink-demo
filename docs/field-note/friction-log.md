# Friction log: Chainlink Data Feeds on Stellar

What I hit while building Two Clocks on 9 and 10 November 2026, four weeks after the 14 October 2026 launch of Chainlink Data Feeds and Data Streams on Stellar. Only the problems that change a developer's experience and that Chainlink can act on. One row per problem: what I was doing, what went wrong, the fix or workaround, and whether it is fixed (on Chainlink's side), open (still there, my workaround is in the row), or by design (not a bug, but worth writing down). The long list, Streams, Candlestick, my own mistakes and tooling included, is in [friction-log-full.md](friction-log-full.md). Repo: https://github.com/kaankacar/stellar-chainlink-demo.

| # | While doing | What went wrong | Fix or workaround | Status |
|---|---|---|---|---|
| C1 | Reading the error table on the Data Feeds Stellar page | It lists `FeedFrozen` as a `ProxyReadError`. The enum has only 50, 51 and 52. A frozen feed panics inside the proxy with `CacheError::FeedFrozen = 109`, which a caller sees as a bare `Error(Contract, #109)`. | The contract maps 109 by hand. Ask: move the row and document 109. | open |
| C2 | Adding the proxy interface to a contract with current tools | There is no crate or npm package for the Stellar interfaces, you copy a trait from the repo. The guide pins `soroban-sdk` 25; 29.0.1, Stellar CLI 26 and Rust 1.95 worked. Chainlink's own interface files use `export = false`, which sdk 29 rejects. | Copied the read functions into the contract. Ask: publish the interfaces as a crate and update the pin. | open |
| C3 | Looking up the ids and labelling the feeds | The feed list page is rendered in the browser; the ids live in the JSON behind it, in a field named `proxyAddress`, with a `0x` prefix the CLI does not want. `FLHY / USD` is labelled asset "Flare", class "Crypto"; it is a tokenized bond ETF. | Read the JSON, stripped the prefix, kept the label with a note. Ask: name the field `dataId`, show the ids as text, and fix the FLHY label. | open |
| C4 | Following the "Install the Stellar CLI" and "Soroban RPC" links in the Data Feeds guides | They point at `soroban.stellar.org`, a retired domain. The CLI link lands on the developers.stellar.org home page. | Used developers.stellar.org directly. Ask: fix the links. | open |
| C5 | Asking the proxy for fewer than 18 decimals | The answer is truncated, not rounded, and `get_min_decimals` is 8 for eight feeds and 18 for `XAUM Reference Rate` and `USPC NAV`, so those two refuse any reduced precision. The docs list the function but give no per-feed value. | Pass 18 everywhere and scale in the consumer. Ask: list each feed's minimum decimals next to its id. | open |
| C6 | Trying to fetch one live Data Streams report with a free Chainlink Platform account | There is no free tier since 1 September 2026 ("All Data Streams subscriptions are paid", from $150 per month per feed). The credentials the Platform gave me are mainnet-only: testnet answers `401 user does not exist`, mainnet lists zero feeds and answers `401 feeds not authorized` for every stream (`404 report not found` the day before), and nothing says "subscribe". The only signed testnet report a developer can get is the April sample in the tutorial, expired since 3 May. The same tutorial says "self-serve, no sales call" and, on the same page, "an allowlisted account in the Data Streams Access Controller". | This note stays on Data Feeds. The sample report still verifies on chain; my contract rejects it as `Expired`. Ask: a testnet tier or a fresh signed testnet report every month, the environment named next to each key, one clear "not subscribed" message, and one access story per page. | open |

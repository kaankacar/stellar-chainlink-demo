# Friction log: Chainlink on Stellar

What I hit while building Two Clocks on 9 and 10 November 2026, four weeks after the 14 October 2026 launch of Chainlink Data Feeds and Data Streams on Stellar. Only the problems that change a developer's experience and that Chainlink can act on. One row per problem: what I was doing, what went wrong, the fix or workaround, and whether it is fixed (on Chainlink's side), open (still there, my workaround is in the row), or by design (not a bug, but worth writing down). The long list, my own mistakes and tooling included, is in [friction-log-full.md](friction-log-full.md). Repo: https://github.com/kaankacar/stellar-chainlink-demo.

| # | While doing | What went wrong | Fix or workaround | Status |
|---|---|---|---|---|
| C1 | Trying to fetch one live Data Streams report with a free Chainlink Platform account | There is no free tier since 1 September 2026 ("All Data Streams subscriptions are paid", from $150 per month per feed). The only signed testnet report a developer can get is the sample in the tutorial, signed on 3 April 2026 and expired on 3 May. The tutorial also says "self-serve, no sales call" and, on the same page, "an allowlisted account in the Data Streams Access Controller". The Stellar verifier has no access controller. | The pull leg of this note runs on the sample: the verifier accepts it, my contract rejects it as `Expired`. Ask: a testnet tier or a fresh signed testnet report every month, a list of the streams the Stellar verifier accepts, and one access story per page. | open |
| C2 | Calling the REST API with the credentials the Platform gave me | Testnet: `401 {"error":"user does not exist"}`. Mainnet: 200 with `{"feeds":[]}`, then `404 report not found` on 9 November and `401 feeds not authorized` on 10 November for every stream. Credentials are per environment and nothing on the credentials page says which one a key belongs to; nothing in the bodies says "subscribe". | Documented the bodies with their dates. Ask: name the environment next to the key, and answer an unsubscribed stream with one clear message. | open |
| C3 | Reading the error table on the Data Feeds Stellar page | It lists `FeedFrozen` as a `ProxyReadError`. The enum has only 50, 51 and 52. A frozen feed panics inside the proxy with `CacheError::FeedFrozen = 109`, which a caller sees as a bare `Error(Contract, #109)`. | The contract maps 109 by hand. Ask: move the row and document 109. | open |
| C4 | Following the Data Streams Stellar tutorial with current tools | There is no crate or npm package for the Stellar interfaces, you copy a trait. The tutorial pins `soroban-sdk = "25"` and `stellar-cli@25.2.0` and warns about Rust 1.91; sdk 29, CLI 26 and Rust 1.95 worked. Its trait declares `verify(...) -> Bytes` while the contract returns `Result<Bytes, ContractError>`, so typed errors are lost. It says `cargo test` runs `real_signature_tests`, which live in Chainlink's repo, not in the scaffold. Its consumer example returns the verified bytes without a freshness check, and the page never says to check `expiresAt`. Chainlink's own interface files use `export = false`, which sdk 29 rejects. | Copied the read functions with the real signatures, wrote my own tests with a mock verifier, and check `expiresAt` in the contract. Ask: publish the interfaces as a crate, update the pins, fix the trait and the test step, and put the `expiresAt` check into the example. | open |
| C5 | Following links in the Chainlink docs | The Data Feeds guides link to `soroban.stellar.org`, a retired domain. The changelog's Stellar link is missing `/tutorials/` and returns 404. The `.md` and `llms-full.txt` copies of the tutorial have the testnet verifier id only; the mainnet id is filled in by the browser. | Took the addresses from the docs source repo and the Stellar post. Ask: fix the three links and put both ids in the text. | open |
| C6 | Labelling the feeds and looking up their ids | The feed list page is rendered in the browser, so the id is only in the JSON behind it, in a field named `proxyAddress` with a `0x` prefix the CLI does not want. `FLHY / USD` is labelled asset "Flare", class "Crypto"; it is a tokenized bond ETF. | Read the JSON, stripped the prefix, kept the label with a note. Ask: name the field `dataId`, and fix the FLHY label. | open |
| C7 | Reading candles from the Candlestick API, which the free account can use | 18-decimal prices arrive as JSON floats, already in float notation in the response text, so ETH and BTC lose their low digits before the client sees them. The symbol format is `XLMUSD`, not the `XLM/USD` used everywhere else, and `XLM/USD` answers "Could not find feedID for symbol". | Parsed the literals as strings and used `XLMUSD`. Ask: serialize as strings or at 8 decimals, and document the symbol format. | open |
